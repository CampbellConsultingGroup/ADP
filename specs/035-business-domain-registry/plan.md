# Implementation Plan: Business Domain Registry and Stage-Capability Mapping

**Branch**: `035-business-domain-registry` | **Date**: 2026-07-10 | **Spec**: [spec.md](spec.md)

## Summary

Add a first-class `BusinessDomain` entity to ADP's business architecture module. Domains partition the L1 capability map into named, classified, compliance-flagged ownership units (strategic/differentiating/commodity). Each L1 capability can belong to at most one domain; the FK uses `ON DELETE SET NULL` so domain deletion never orphans capabilities. Also add a `value_stream_stage_capabilities` many-to-many join table so architects can record which capabilities enable each stage — the horizontal-thread-through-vertical-blocks link that makes the value stream model analytically useful. All changes stay within the existing `adp.business` module and `web/src/business/` frontend directory, keeping the backend API the sole integration boundary for a future landing page spec.

## Implementation Phases

### Phase 1: Setup (migration + foundational models)

**Migration 009** — `src/adp/store/migrations/versions/009_business_domain_registry.py`
- CREATE TABLE `business_domains`: id (VARCHAR 36 PK), name (VARCHAR 255 NOT NULL), scope_statement (TEXT), classification (TEXT NOT NULL CHECK IN strategic/differentiating/commodity), org_unit (VARCHAR 255), risk_flags (TEXT[] NOT NULL DEFAULT '{}'), created_at/updated_at (TIMESTAMPTZ NOT NULL)
- Index: `ix_business_domains_name` on name
- ALTER TABLE `business_capabilities` ADD COLUMN `domain_id` VARCHAR(36) REFERENCES business_domains(id) ON DELETE SET NULL
- Index: `ix_business_capabilities_domain_id` on domain_id
- CREATE TABLE `value_stream_stage_capabilities`: stage_id (VARCHAR 36, FK → value_stream_stages.id CASCADE), capability_id (VARCHAR 36, FK → business_capabilities.id CASCADE), PRIMARY KEY (stage_id, capability_id)
- Index: `ix_vssc_capability_id` on capability_id

**Pydantic models** — extend `src/adp/business/models.py`
- DomainClassification = `Literal["strategic", "differentiating", "commodity"]`
- BusinessDomain, DomainSummary, DomainDetail (extends BusinessDomain + capabilities list), DomainListResponse
- BusinessDomainCreate (name not-blank validator, risk_flags blank check + dedup), BusinessDomainUpdate (all optional)
- Extend BusinessCapability: add `domain_id: str | None = None`, `domain_name: str | None = None`
- CapabilityDomainAssign (domain_id: str | None)
- StageCapabilityRef (cap id, name, level, domain_id, domain_name), StageCapabilityLinkCreate (cap_id not-blank), StageCapabilitiesResponse
- DuplicateStageCapError, StageCapNotFoundError

**Unit tests** — extend `tests/unit/business/test_models.py`
- TestBusinessDomainCreate: blank name → error, blank risk_flag → error, duplicate flags deduplicated, invalid classification → error, extra fields → error, valid full create
- TestCapabilityDomainAssign: null domain_id accepted, uuid string accepted, extra fields → error
- TestStageCapabilityLinkCreate: blank → error, whitespace stripped to valid id

### Phase 2: US1 — Domain CRUD

**Store functions** — extend `src/adp/business/store.py`
- Add `_domains` SA Table; add `domain_id` column to `_capabilities` SA Table definition
- Extend `_row_to_capability()` to join `business_domains` for `domain_name` (LEFT JOIN on domain_id)
- `list_domains(session)` → ordered by name; LEFT JOIN COUNT of caps per domain
- `get_domain(domain_id, session)` → DomainDetail with cap list
- `create_domain(body, session)` → BusinessDomain
- `update_domain(domain_id, body, session)` → BusinessDomain | None
- `delete_domain(domain_id, session)` → bool (DB CASCADE handles SET NULL)

**Integration tests** — extend `tests/integration/test_business_api.py`
- POST domain 201, all fields returned; GET list ordered; GET detail caps=[]; PUT scope; DELETE 204 + cap survives with domain_id null; GET nonexistent 404

**Router** — extend `src/adp/business/router.py`
- GET /domains, POST /domains (201), GET /domains/{id} (DomainDetail), PUT /domains/{id}, DELETE /domains/{id} (204)

**Frontend hooks** — extend `web/src/api/business.ts`
- TS interfaces + `useDomains()`, `useDomain(id)`, `useCreateDomain()`, `useUpdateDomain(id)`, `useDeleteDomain()`

**DomainList.tsx** — list of DomainSummary cards with classification badge, cap count, Add button

**DomainForm.tsx** — create/edit form: name input, scope_statement textarea, classification select (3 options), org_unit input, risk_flags comma-separated text input

**DomainDetail.tsx** — domain metadata display + edit button + L1 cap list with assignment panel (picker for unassigned L1 caps, Remove button per assigned cap)

**BusinessPage: Domains tab** — add `"domains"` to BusinessTab union; render DomainList → DomainDetail with `selectedDomainId` state

### Phase 4: US3 — Stage-Capability Mapping
