# Data Model: Requirements Intake & Normalization

**Branch**: `006-requirements-intake` | **Date**: 2026-07-01  
**Source**: `src/adp/intake/models.py`

This spec produces `Requirement` records (defined in ADP-SPEC-001) via a temporary pipeline of intake-specific entities. Intake entities are transient and never stored beyond the operation TTL.

---

## `SubmissionMode` (StrEnum)

| Value | Description |
|---|---|
| `bulk_text` | Paste or typed plain text or Markdown containing multiple requirements |
| `structured_form` | One requirement statement per submission (single-field entry) |

---

## `RequirementKind` (StrEnum — mirrors ADP-SPEC-001)

| Value | Description |
|---|---|
| `functional` | What the system must do |
| `non-functional` | Quality attributes (performance, security, scalability) |
| `constraint` | External limits that bound solution choices |
| `driver` | Strategic goal or business motivation |

---

## `VerificationStatus` (StrEnum)

| Value | Meaning |
|---|---|
| `verified` | `source_excerpt` is a verbatim (case-insensitive) substring of the submitted text |
| `unverified` | Excerpt not found verbatim; proposal is flagged for extra scrutiny |

---

## `ProposalStatus` (StrEnum)

Lifecycle of an `ExtractedProposal` before it enters (or is rejected from) the model.

| Value | Meaning |
|---|---|
| `pending` | Awaiting human action |
| `confirmed` | Human confirmed; `Requirement` written to model |
| `edited_confirmed` | Human edited statement before confirming |
| `rejected` | Human rejected; not entered into model |
| `expired` | TTL elapsed; not entered into model |

---

## `IntakeSubmission`

The input package provided by the architect. Never persisted beyond the extraction job.

| Field | Type | Notes |
|---|---|---|
| `submission_id` | `str` | UUID4; stable identifier for the job |
| `mode` | `SubmissionMode` | How the text was submitted |
| `text` | `str` | Raw source text (Markdown or plain text); max 20,000 characters |
| `submitted_by` | `str` | `ApiPrincipal.principal_id` from ADP-SPEC-004 |
| `submitted_at` | `datetime` | UTC timestamp |
| `operation_id` | `str` | The ADP-SPEC-003 operation handle id this job is attached to |

**Not stored**: `text` is held in memory only during the extraction job and discarded after.

---

## `ExtractionJob`

The async AI task state. Attached to the `OperationHandle` from ADP-SPEC-003.

| Field | Type | Notes |
|---|---|---|
| `job_id` | `str` | Same as `operation_id` |
| `status` | `OperationStatus` | From ADP-SPEC-003 (`pending`, `running`, `completed`, `failed`) |
| `proposal_ids` | `list[str]` | IDs of all proposals generated by this job |
| `error` | `str \| None` | Error message if status is `failed` |
| `span_id` | `str \| None` | OTel span id for QG-11 traceability |

---

## `ExtractedProposal`

An AI-proposed requirement before human confirmation. Stored transiently in the operation store (TTL 24h).

| Field | Type | Required | Notes |
|---|---|---|---|
| `proposal_id` | `str` | Yes | UUID4; stable within the job's TTL |
| `operation_id` | `str` | Yes | Parent job id |
| `draft_statement` | `str` | Yes | AI-generated requirement statement |
| `kind` | `RequirementKind` | Yes | AI-classified kind |
| `source_excerpt` | `str` | Yes | Verbatim (or near-verbatim) substring from submitted text |
| `verification_status` | `VerificationStatus` | Yes | `verified` or `unverified` |
| `confidence` | `float` | Yes | 0.0–1.0; AI extraction confidence |
| `proposed_links` | `list[str]` | No | Knowledge base ids the LLM identified as referenced principles/capabilities |
| `status` | `ProposalStatus` | Yes | Default `pending` |
| `confirmed_statement` | `str \| None` | No | Set if architect edits statement before confirming |
| `confirmed_by` | `str \| None` | No | `ApiPrincipal.principal_id` of confirming actor |
| `confirmed_at` | `datetime \| None` | No | UTC timestamp of confirmation |
| `requirement_id` | `str \| None` | No | The `Requirement.id` assigned after confirmation |

---

## `ExtractionSpan`

The telemetry payload emitted per job (QG-11 / FR-006). Emitted regardless of success or failure.

| Field | Type | Notes |
|---|---|---|
| `operation_id` | `str` | Parent job id |
| `correlation_id` | `str` | API request correlation ID from ADP-SPEC-003 |
| `model` | `str` | LLM model identifier |
| `endpoint` | `str` | Base URL of the LLM endpoint (no API key) |
| `source_char_count` | `int` | Character count of submitted text |
| `input_tokens` | `int` | Tokens in the LLM request |
| `output_tokens` | `int` | Tokens in the LLM response |
| `cost_usd` | `float` | Estimated cost at configured per-token rates |
| `proposal_count` | `int` | Number of proposals generated |
| `proposal_ids` | `list[str]` | Ids of generated proposals |
| `latency_ms` | `float` | End-to-end extraction latency |
| `error` | `str \| None` | Error message if extraction failed |

## Pipeline State Machine

```
IntakeSubmission (input)
        │
        ▼
ExtractionJob (status=pending)
        │
        ▼ [async]
LLMClient.extract(submission.text)
        │
        ├── LLMResponseParser.parse() → list[ExtractedProposal]
        │       ├── SourceExcerptVerifier.verify() → verification_status per proposal
        │       └── KnowledgeLinker.link() → proposed_links per proposal
        │
        ├── IntakeTelemetry.emit(ExtractionSpan)
        │
        └── ExtractionJob.status = completed
                │
                ├── [architect confirms] → ProposalStatus.confirmed
                │       └── Requirement written to DesignStore (ADP-SPEC-002)
                │       └── AuditEntry written (ADP-SPEC-004 / QG-13)
                │
                ├── [architect edits + confirms] → ProposalStatus.edited_confirmed
                │
                ├── [architect rejects] → ProposalStatus.rejected
                │
                └── [TTL expires] → ProposalStatus.expired
```

---

## Relationship to ADP-SPEC-001

When an `ExtractedProposal` is confirmed, a `Requirement` is created in the canonical model:

| `ExtractedProposal` field | → `Requirement` field |
|---|---|
| `confirmed_statement` or `draft_statement` | `description` |
| `kind` | `priority` (mapped: functional → must, etc.) |
| `proposal_id` | `provenance` (tracks origin) |
| `proposed_links` (confirmed) | `tags` (pending ART-XI link spec) |
| `submission_id` | embedded in `provenance` |
